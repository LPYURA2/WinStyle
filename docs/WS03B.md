# WS-03B — первый контролируемый Win32 API
Собственный PE импортирует GetCurrentProcessId из kernel32.dll. Собственная build-only DLL-заглушка создаёт import library; её код не загружается и не исполняется. Build-time extractor проверяет узкий профиль, один именованный импорт, IAT, .text, отсутствие релокаций и writable sections. Встроенный образ в отдельном Linux x86-64 child получает в IAT адрес единственного заранее выбранного ms_abi адаптера. Адаптер возвращает Linux PID как экспериментальную модель Windows PID. Child вызывает entry(7), проверяется PID+7 и один вызов, тест сверяет PID с Popen.pid. Модельные страницы RW при подготовке, затем R и RX только .text. Ограничения CPU/AS/core/output. 7 новых тестов, ожидаемо 150; CI пока не проверен, локально не запускалось.
Только доверенный собственный fixture, не универсальный loader, не реализация kernel32.dll, не sandbox. Никаких произвольных API, внешнего PE, прямых системных вызовов гостя или исполнения импортированной DLL. Требуется отдельная проверка границы syscalls и изоляции до стороннего кода. R/RX не защищает от произвольных native syscalls. Старые sanitizers относятся к WS-01, новый child ими ещё не покрыт. Следующий этап WS-03C — проверяемая граница host syscall и протокол разрешённых операций на доверенных fixtures. StyleOS и ядро не изменяются.
