# Будущая интеграция WinStyle со StyleOS — предложение, не утверждённый ABI
Вся разработка сейчас только в LPYURA2/WinStyle. Никаких обращений к LPYURA2/OS. Реальную интеграцию согласовывать отдельно.
## Продукт
Проводник передаёт .exe и позже .msi штатному диспетчеру запуска; .tea остаётся в нативной среде. WinStyle анализирует тип PE, автоматически выбирает профиль, готовит зависимости, запускает портативный EXE или установщик. Установленная программа регистрируется в меню, параметрах и процессах. Не требовать ручной настройки VM/контейнера/префикса; внутренние профили допускаются. Не вмешиваться в лицензии и активацию. Диагностика конкретных отказов.
## Границы
Пользовательский runtime отдельно от ядра. Минимальный процессный контекст и обязательные импорты при старте, отложенные импорты и динамические DLL по запросу. Не обещать, что любая DLL лениво загружается: статические зависимости и инициализация обязательны. Изоляция адресных пространств, системные вызовы Windows не должны напрямую попадать в чужую ABI ядра. Ограниченные права, брокер ресурсов. W^X, исключения, TLS, потоки, дескрипторы, файлы, реестр, сеть, графика, звук, IPC. Не загружать Windows-драйверы в ядро. Совместимость не отменяет защиту.
## Интерфейс
Версионированный контракт будущего host-адаптера: inspect, prepare, install, launch, stop, uninstall, diagnose; операции памяти, потоков, файлов и GUI через контролируемые сервисы. Названия условны. Пока тестировать на автономном mock/host, не предполагать наличие этих API в StyleOS. Отдельные неизменяемые версии runtime и пользовательские данные, атомарная установка/откат, совместимость версий протокола; обновление WinStyle не требует замены ядра при стабильном контракте.
## Приёмка
До интеграции — проверка автономного запуска и отказов, независимый аудит, матрица поддерживаемых приложений, тесты изоляции, замеры CPU/RAM/запуска/звука, лицензии зависимостей. Затем согласование API с владельцем, отдельный план интеграции, тестовая сборка и rollback. Никакой гарантии запуска всех Windows-программ.

## Две равноправные среды исполнения (уточнение владельца)
WinStyle — штатный системный компонент рядом с родной средой .tea, а не отдельный пользовательский эмулятор. Общие рабочий стол, диспетчер приложений, настройки, Проводник и системные службы. Раздельные ABI, runtime, жизненный цикл, данные и версии. Независимое обновление при сохранении стабильного контракта, без необходимости перезаписывать ядро. Проектировать адаптер так, чтобы позже другие среды могли подключаться по аналогичной схеме; Android не входит в текущий этап. Нельзя предполагать готовность конкретных API StyleOS. Реальная интеграция только по отдельному разрешению.
