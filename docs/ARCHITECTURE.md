# Архитектура и контракт (предложение WS-01)
A: собственный PE loader, NT/Win32 среда, адаптер StyleOS. Высокий контроль, высокая стоимость API. B: адаптация открытых компонентов, включая Wine, оценить POSIX, лицензии и переносимость; не делать выводов о скорости без измерений. C: гостевая Windows, требует ресурсы и лицензии, не основа продукта. D: трансляция ISA для ARM, не заменяет API. Рекомендация исследовать A+B, без утверждения.
Контракт будущего адаптера (не предположение о готовности ядра):
1. Память: резервирование, отображение, защита, W^X по умолчанию, контролируемая политика JIT.
2. Процессы: раздельные адресные пространства, потоки, ожидание, исключения, TLS, права и ресурсы.
3. Объекты: дескрипторы, события, mutex, semaphore, shared memory, IPC, наследование и закрытие.
4. Файлы и реестр: пути, регистр, блокировки, Unicode, права, виртуальное отображение дисков и отдельные данные.
5. ABI: Microsoft x64, shadow space, выравнивание, TEB/PEB, unwind/SEH; прямой Windows syscall не должен вызывать произвольные сервисы хоста. Проверенная изоляция до недоверенного исполнения.
6. GUI/GDI/DirectX, звук, MIDI, сеть, clipboard, Deep Drop — посредники системных сервисов. Не загружать Windows-драйверы в ядро.
7. Установщик: транзакции, откат, зависимости, учёт, EXE/MSI, удаление, меню.
8. Диагностика: неподдерживаемые API, контролируемый отказ, версии runtime и скрытые от пользователя профили.
