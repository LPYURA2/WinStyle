# WinStyle — правила разработки

## Обязательная граница
- Единственный разрешённый репозиторий: `LPYURA2/WinStyle`.
- Не обращаться к `LPYURA2/OS`, не изменять StyleOS, Style Kernel, их ветки, сборки, документацию и настройки.
- Разрабатывать и тестировать WinStyle автономно. Интерфейсы интеграции моделировать локально. Реальная интеграция только по отдельному явному разрешению владельца.

## Цель
Скачал Windows EXE, установил, запустил, работаешь. Без ручной настройки виртуальных машин, контейнеров или префиксов. Приоритет исследования — прямое исполнение на x86-64, изоляция приложений, адаптация Windows API/ABI; архитектура не утверждена окончательно.

## Процесс
- После первоначальной инициализации каждый этап выполнять в отдельной ветке. Не объединять непроверенные изменения с main.
- Сохранять исходники, отчёты, результаты тестов и точку продолжения. Отделять лабораторные результаты от проверки в StyleOS.
- Использовать готовые проверенные решения, если это технически оправдано и лицензии совместимы. Не использовать утечки исходников Windows, не распространять нелегальные копии ПО и активаторы. Не вмешиваться в лицензирование сторонних приложений. Проверять безопасность независимо от источника EXE.
- Не исполнять неизвестные EXE без подходящей изоляции. Не ослаблять защиту ядра ради совместимости.

## Точка входа
Читать docs/PROJECT.md, docs/STATE.md и docs/NEXT.md. Проверять фактические SHA и CI. Main — проверенная база; каждый этап — отдельная ветка со своим README и отчётом. Проект будущего интерфейса: docs/INTEGRATION.md; не менять StyleOS.
